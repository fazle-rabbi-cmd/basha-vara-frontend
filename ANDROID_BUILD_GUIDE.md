## Prerequisites

### What You Need Already Installed ✅
- ✅ Node.js (version 20+)
- ✅ Android Studio (you've installed this)
- ✅ Capacitor packages (@capacitor/core, @capacitor/cli, @capacitor/android)
- ✅ Android platform added to Capacitor

### What You Need to Verify

#### 1. Java JDK
Android Studio usually includes JDK, but verify it's configured:

**In Android Studio:**
1. File → Settings → Build, Execution, Deployment → Build Tools → Gradle
2. Check "Gradle JDK" is set to a valid JDK (11 or higher)

**If not set:**
- Download JDK 11 or higher from: https://adoptium.net/
- Set JAVA_HOME environment variable

#### 2. Android SDK
**In Android Studio:**
1. Tools → SDK Manager
2. Ensure these are installed:
   - Android 13.0 (API level 33) or higher
   - Android SDK Build-Tools
   - Android SDK Platform-Tools
   - Android SDK Command-line Tools

#### 3. Environment Variables (Windows)

**Check these are set:**
- `ANDROID_HOME` - Points to your Android SDK
- `JAVA_HOME` - Points to your JDK

**To check in PowerShell:**
```powershell
echo $env:ANDROID_HOME
echo $env:JAVA_HOME
```

**To set if missing:**
```powershell
$env:ANDROID_HOME = "C:\Users\YourUsername\AppData\Local\Android\Sdk"
$env:JAVA_HOME = "C:\Program Files\Android\Android Studio\jbr"
```

## Understanding the Architecture

### How Capacitor Works

```
Your Next.js Web App
        ↓
    Capacitor
        ↓
   Native Android App
```

**What Capacitor Does:**
1. Takes your built Next.js app (from `.next` folder)
2. Wraps it in a native Android WebView
3. Provides a bridge to native device features (camera, geolocation, etc.)
4. Packages it as a standard Android APK/AAB

### Key Files to Understand

**capacitor.config.ts** - Configuration file:
```typescript
{
  appId: 'com.bashavara.app',  // Unique app identifier
  appName: 'Basha Vara',       // Display name
  webDir: '.next',             // Where your built Next.js app is
  server: {
    url: 'http://localhost:3000',  // For development (live reload)
    androidScheme: 'https',
  }
}
```

**android/ folder** - Generated by Capacitor:
- Contains the actual Android project
- Synced from `.next` folder via `npx cap sync android`
- **Never edit this folder directly** - changes will be overwritten

## Development vs Production Builds

### Development Build (Live Reload)

**Purpose:** Test changes quickly without rebuilding

**How it works:**
- Next.js dev server runs at `http://localhost:3000`
- Capacitor app connects to this server
- Changes appear instantly in the app

**When to use:**
- During active development
- Testing UI changes
- Debugging

**Configuration:**
```typescript
// capacitor.config.ts
server: {
  url: 'http://localhost:3000',  // Points to dev server
  cleartext: true,               // Allow HTTP (not HTTPS)
}
```

**Process:**
1. Start backend: `cd backend && npm run start:dev`
2. Start frontend: `cd frontend && npm run dev`
3. Sync: `npx cap sync android`
4. Open Android Studio and run app
5. App connects to localhost:3000 for live reload

### Production Build (Standalone)

**Purpose:** Create distributable APK/AAB

**How it works:**
- Next.js builds to static files in `.next` folder
- Capacitor copies these files into the Android app
- App runs entirely on the device (no server needed)

**When to use:**
- Creating APK for testing
- Creating AAB for Play Store
- Distributing to testers

**Configuration:**
```typescript
// capacitor.config.ts
server: {
  androidScheme: 'https',
  // No 'url' field - app uses bundled files
}
```

**Process:**
1. Build frontend: `cd frontend && npm run build`
2. Sync: `npx cap sync android`
3. Open Android Studio and build APK/AAB
4. App runs standalone on device

**Step 2: Start Your Frontend Dev Server**

Keep this running in another terminal.

**Step 3: Update Capacitor Config (if port changed)**

```typescript

  url: 'http://localhost:3001',  // Update port
  cleartext: true,
}
```

**Step 4: Sync to Android**
```bash
cd E:\basha-vara\frontend
npx cap sync android
```

**Step 5: Open Android Studio**
```bash
npx cap open android
```

**Step 6: Run on Emulator or Device**
1. In Android Studio, wait for Gradle sync to complete
2. Click the device dropdown in the toolbar
3. Select an emulator or connected device
4. Click the green "Run" button (▶️)
5. Wait for the app to build and install

**Step 7: Test the App**
- The app should open and connect to your dev server
- Make changes to the web code
- Refresh the app to see changes

#### Option B: Production Build (For Distribution)

Use this to create a standalone APK/AAB.

**Step 1: Update Capacitor Config for Production**
Edit `frontend/capacitor.config.ts`:
```typescript
const config: CapacitorConfig = {
  appId: 'com.bashavara.app',
  appName: 'Basha Vara',
  webDir: '.next',
  server: {
    androidScheme: 'https',
    // Remove 'url' field for production
  },
  plugins: {
    CapacitorHttp: {
      enabled: true,
    },
  },
};
```

**Step 2: Build the Frontend**
```bash
cd E:\basha-vara\frontend
npm run build
```

**Step 3: Sync to Android**
```bash
npx cap sync android
```

**Step 4: Open Android Studio**
```bash
npx cap open android
```

**Step 5: Build Debug APK**
1. In Android Studio menu: Build → Build Bundle(s) / APK(s) → Build APK(s)
2. Wait for build to complete
3. Click "locate" when prompted
4. APK is at: `android/app/build/outputs/apk/debug/app-debug.apk`

**Step 6: Install and Test**
- Transfer APK to your Android device
- Enable "Install from Unknown Sources" in settings
- Install and test the APK

2. Allow USB debugging on phone (prompt will appear)
3. In Android Studio, select your phone from device dropdown
4. Click Run button

## Building for Production (Play Store)

### Understanding APK vs AAB

**APK (Android Package Kit):**
- Direct installable file
- Used for testing and sideloading
- Cannot be uploaded to Play Store (deprecated)

**AAB (Android App Bundle):**
- Required for Play Store
- Smaller download size (Google optimizes it)
- Required format for Play Store distribution

### Step 1: Generate Signing Keystore

**What is a Keystore?**
- A secure file that contains your digital signature
- Required for releasing apps
- Protects your app identity
- Keep it safe - if lost, you can't update your app

**Generate Keystore:**
```bash
# Open command prompt in any directory
keytool -genkey -v -keystore basha-vara-release.keystore -alias basha-vara -keyalg RSA -keysize 2048 -validity 10000
```

**You'll be prompted for:**
- Keystore password (remember this!)
- First and Last Name
- Organizational Unit
- Organization
- City/State
- Country Code (BD for Bangladesh)
- Key password (use same as keystore password)

**Example answers:**
```
Enter keystore password: YourStrongPassword123
Re-enter new password: YourStrongPassword123
What is your first and last name? Fazle Rabbi
What is the name of your organizational unit? Development
What is the name of your organization? Basha Vara
What is the name of your City or Locality? Dhaka
What is the name of your State or Province? Dhaka
What is the two-letter country code? BD
Enter key password for <basha-vara>: YourStrongPassword123
```

**Important:**
- Save the keystore file in a secure location
- Never commit it to Git
- Never share it
- Keep the password safe

### Step 2: Configure Signing in Android Studio

**Open build.gradle:**
1. In Android Studio, open: `android/app/build.gradle`
2. Add signing configuration before `android` block:

```gradle
android {
    // ... existing config ...
    
    signingConfigs {
        release {
            storeFile file('../../basha-vara-release.keystore')
            storePassword 'YourStrongPassword123'
            keyAlias 'basha-vara'
            keyPassword 'YourStrongPassword123'
        }
    }
    
    buildTypes {
        release {
            signingConfig signingConfigs.release
            minifyEnabled true
            proguardFiles getDefaultProguardFile('proguard-android.txt'), 'proguard-rules.pro'
        }
    }
}
```

**Alternative: Use Environment Variables (More Secure)**

```gradle
android {
    signingConfigs {
        release {
            storeFile file(System.getenv("KEYSTORE_FILE") ?: '../../basha-vara-release.keystore')
            storePassword System.getenv("KEYSTORE_PASSWORD")
            keyAlias System.getenv("KEY_ALIAS") ?: 'basha-vara'
            keyPassword System.getenv("KEY_PASSWORD")
        }
    }
}
```

### Step 3: Build Release AAB

**In Android Studio:**
1. Build → Generate Signed Bundle / APK
2. Select "Android App Bundle"
3. Click Next
4. Choose or create keystore:
   - Click "Choose existing" if you generated one
   - Or "Create new" to generate in Android Studio
5. Enter keystore details
6. Select "release" build variant
7. Click Finish
8. Wait for build to complete
9. Click "locate" when prompted

**AAB location:**
`android/app/build/outputs/bundle/release/app-release.aab`

### Step 4: Upload to Play Store

**Requirements:**
1. Google Play Developer Account ($25 one-time)
2. Complete store listing:
   - App name: "Basha Vara"
   - Short description (80 chars)
   - Full description
   - Screenshots (at least 2)
   - App icon (512x512)
   - Feature graphic (1024x500)
   - Privacy policy URL
   - Content rating questionnaire

**Steps:**
1. Go to Google Play Console: https://play.google.com/console
2. Create new app
3. Fill in app details
4. Upload AAB file
5. Complete store listing
6. Set pricing (Free)
7. Submit for review
8. Wait 1-3 days for approval

## Troubleshooting

### Issue 1: Gradle Sync Fails

**Error:** "Gradle sync failed"

**Solutions:**
1. Check internet connection
2. File → Invalidate Caches → Invalidate and Restart
3. Update Android Studio: Help → Check for Updates
4. Check JDK version in File → Settings → Build Tools → Gradle

### Issue 2: "Could not resolve files"

**Error:** Build fails with dependency resolution errors

**Solutions:**
1. Check internet connection
2. In `android/build.gradle`, update repositories:
```gradle
repositories {
    google()
    mavenCentral()
}
```
3. Clean build: Build → Clean Project
4. Rebuild: Build → Rebuild Project

### Issue 3: App Crashes on Startup

**Error:** App opens then immediately closes

**Solutions:**
1. Check logcat in Android Studio (bottom tab)
2. Look for errors in red
3. Common causes:
   - Missing permissions in AndroidManifest.xml
   - Incorrect API URL
   - Backend not accessible
   - Network not available

### Issue 4: Maps Don't Show

**Error:** Map area is blank

**Solutions:**
1. Check network permissions in `android/app/src/main/AndroidManifest.xml`:
```xml
<uses-permission android:name="android.permission.INTERNET" />
```
2. Ensure backend API is accessible
3. Check browser console for errors (in dev mode)
4. Try with production build (different network stack)

### Issue 5: "INSTALL_FAILED_UPDATE_INCOMPATIBLE"

**Error:** Can't install app over existing version

**Solutions:**
1. Uninstall existing app from device
2. Try installing again
3. Or increment version in `android/app/build.gradle`:
```gradle
defaultConfig {
    versionCode 2  // Increment this
    versionName "1.0.1"
}
```

### Issue 6: App Won't Connect to Backend

**Error:** API calls fail in app

**Solutions:**
1. For dev build: Ensure backend is running on localhost
2. For production: Update API URL in environment variables
3. Check if device can reach your computer:
   - Dev build: Use your computer's IP address instead of localhost
   - Example: `http://192.168.1.100:4000/api/v1`
4. Check firewall settings

## Common Questions

### Q: Can I test without Android Studio?

**A:** Partially. You can build the APK using command line, but:
- You still need Android SDK installed
- Android Studio is the easiest way
- Command line is complex and error-prone

### Q: Do I need a Mac for Android development?

**A:** No. Android development works on Windows, Mac, and Linux.

### Q: Can I use React Native instead?

**A:** You could, but:
- Would require rewriting the entire frontend
- Much more work
- Capacitor is better for this project (reuses existing code)

### Q: How do I update the app after building?

**A:** 
1. Make changes to web code
2. Run `npm run build`
3. Run `npx cap sync android`
4. Rebuild APK/AAB in Android Studio
5. Distribute new version

### Q: Can I use the app offline?

**A:** Limited offline support:
- Production build has static files cached
- API calls require internet
- Would need additional work for full offline support

### Q: How do I add push notifications?

**A:** Steps:
1. Install Firebase Cloud Messaging
2. Configure Firebase project
3. Add `@capacitor/push-notifications` plugin
4. Implement notification handling in app
5. This is deferred to Phase 6.5

### Q: How do I add camera support?

**A:** Steps:
1. Install `@capacitor/camera` plugin
2. Add camera permissions to AndroidManifest.xml
3. Implement camera in your app
4. This is deferred (requires backend file upload endpoint)

### Q: What's the difference between debug and release builds?

**A:**
- **Debug:** For testing, can be installed easily, not signed
- **Release:** For distribution, signed, optimized, smaller size

### Q: Can I distribute APKs without Play Store?

**A:** Yes, you can:
- Send APK directly to testers
- Host on your website
- Use alternative app stores
- This is useful for beta testing

### Q: How do I change the app icon?

**A:** 
1. Create 1024x1024 PNG icon
2. Place in `frontend/resources/icon.png`
3. Run `npx cap assets`
4. Or manually replace icons in `android/app/src/main/res`

### Q: How do I add a splash screen?

**A:**
1. Create 2732x2732 PNG splash
2. Place in `frontend/resources/splash.png`
3. Run `npx cap assets`
4. Or manually configure in `capacitor.config.ts`
